# 历史街区公共文化空间排期

历史街区把公益音乐会、非遗体验、城市漫游集合点和线上剧场户外放映排进有限的
院落与广场。本服务在领域层（纯标准库 Python）实现：

- 场地分区、文保条件、噪声窗口（居民安静时段）、容量、无障碍路线、设备进出
  通道、消防通道、周边居民约定**按版本维护**；
- 文化机构活动先**暂占**空间与共用设备，文保、消防、属地管理三方意见齐全且
  全部同意后，按当前版本复核通过才转为**确定档期**；
- 并发申请在同一把锁内完成“读状态—校验—追加事件”，**不能同时锁定同一空间
  或共用设备**；另支持事件流版本号乐观锁；
- 暴雨、临时修缮、居民紧急通行、已售活动取消触发**迁场 / 缩容 / 退款建议**，
  列明可行替代、触碰的红线与受影响对象（机构、已购票观众、居民、协同部门）；
- 系统**不自动批准高风险例外**：高风险方案保持 `PENDING`，仅负责人显式决定
  后才可执行；
- 工作人员可查询某一天每块空间**为什么可用/不可用**（连续时段切片 + 稳定原因
  码与证据），并能从一次投诉反查**当时批准依据、现场调整、后续恢复**的完整
  时间线。

所有状态变更都是不可变事件（事件溯源），事件流可落盘为 JSON Lines 并完整回放，
资料中不含真实个人信息、生产连接或外部账号。

## 目录

- `src/models.py`：值对象与枚举（版本化空间/设备、申请、意见、扰动、方案、投诉）。
- `src/store.py`：事件存储、线程安全追加、乐观并发、事件流归约。
- `src/rules.py`：排期硬规则（容量、安静时段、封闭窗口、无障碍、空间/设备占用）。
- `src/service.py`：命令侧（版本发布、暂占、意见、确认、扰动、方案决定与执行）。
- `src/queries.py`：查询侧（`explain_day` 可用性解释、`trace_complaint` 投诉溯源）。
- `data/sample.json`：用于核对事件信封格式的虚构事件。
- `tests/`：21 个单元测试，覆盖上述关键规则与并发场景。

## 关键约定

| 规则 | 行为 |
| --- | --- |
| 版本链 | 空间/设备新版本号必须递增；发布时旧版本封口，历史档期保留确认时依据 |
| 暂占 | 硬冲突即拒（空间、共用设备互斥），但不要求三方意见 |
| 确认 | 文保 + 消防 + 属地意见齐全且同意，并按当前版本重新校验 |
| 扰动 | 自动只生成建议；常规方案办公室可执行，高风险必须负责人批准 |
| 迁场/缩容 | 执行时再次复核；目标不再合规则拒绝 |
| 已售取消 | 自动生成退款建议并列出已购票观众等受影响对象 |
| 可追溯 | 投诉溯源给出确认依据快照、多代场地分配、方案决定人与恢复记录 |

原因码（`CAPACITY`、`QUIET_HOURS`、`BLOCKED_WINDOW`、`ACCESSIBLE_ROUTE`、
`SPACE_OCCUPIED`、`EQUIPMENT_OCCUPIED` 等）在命令拦截与可用性解释中一致使用。
